# 需求与验收

## 1. 解决什么问题

招聘方在 BOSS 招聘端会收到主动投递。投递量一大，人工逐份看在线简历就没有意义——
真正需要的不是"多一个 AI 推荐"，而是**按我自己的标准，把来人排个序，并告诉我为什么**。

## 2. 用户

- 个体老板、10 人以下小团队
- 自己发职位、自己筛人，没有 HR 团队，也不接 ATS
- 有招聘端账号（企业认证），愿意自己动手点按钮，但不愿意一份份读简历

## 3. 范围

**做（V1）**

- 读取"牛人发起"的会话/投递列表
- 打开候选人在线简历，抽取结构化字段
- 按老板写的需求做硬性过滤 + 软性打分 + 排序
- 输出名单：分数、命中的条件、缺的条件、可解释理由
- 生成沟通草稿（本地生成，复制走人，不发送）
- 本地存储（SQLite），全程零网络外发

**不做（V1 明确排除）**

- 任何发送动作：打招呼、回复、发消息
- 任何付费请求：索要附件简历、换电话、换微信、面试邀请
- 推荐牛人 / 搜索牛人（"主动找人"路线）
- 代理登录、绕过验证码、规避风控
- 云端服务、账号体系、多人协作

## 4. 漏斗

```
投递列表（免费） → 在线简历（免费） → 打分排序（本地） → 名单
                                                    ↓
                                        人看过、点了"同意"
                                                    ↓
                                        索要附件简历（付费，V1 不做，人工在平台点）
```

**在线简历 = 初筛依据；附件简历 = 二次筛选，只在人工确认后发生。**

## 5. 验收标准

| 编号 | 标准 | 怎么验 |
|---|---|---|
| A1 | 能在 mock 数据上跑通完整链路 | `bosscreen demo` 输出名单 |
| A2 | 缺字段记为"未知"，不记为"不满足" | 单测覆盖 |
| A3 | 同一个人多次投递只出现一次 | 单测覆盖 |
| A4 | 每条打分给出可读理由 | 名单里能看到命中/缺失条目 |
| A5 | 选择器不写在代码里 | 改 `config/selectors.*.json` 即可适配 |
| A6 | 启动自检能报告"页面结构是否可读" | `bosscreen doctor`（连上 Chrome 后检查容器是否命中） |
| A7 | 全链路无对外写操作 | 代码里不存在发送函数 |
| A8 | 采集管线在样例页面上端到端跑通 | `collect --fixture` + `tests/test_collector_live.py` |
| A9 | 未校准的选择器不允许上真机 | `collect` 在 `calibrated=false` 时返回 1 |
| A10 | 需求能在看板上改，改完立刻重算 | 点"编辑需求"保存，名单与标题同时变 |
| A11 | 需求存不上时如实告诉用户 | 单测：`on_save` 抛错 → `payload.saved.ok=false`，弹窗里显示原因 |
| A12 | 列表滚动能把隐藏的候选人滚出来 | `collect --list-url …/list-scroll.html` 输出 9 条并写明"认为到底" |
| A13 | 新标签页没加载完时不能读到空白页 | 单测：紧接着 `detail_page` 打开详情页仍能读到姓名/学历 |
| A14 | 选择器逐个自检，错了要说清哪一项 | `check --kind list/detail --page …` 打出每字段命中数与样本；容器错退出 3 |
| A15 | 名单能导出成表格 | 看板"导出 CSV"或 `bosscreen export` 出 13 列、UTF-8 BOM、未知字段留空 |
| A16 | 多份需求能并存并切换 | 存两份需求 → 下拉里有两项 → 切换后名单重排、库里不多写一行 |

## 6. 非目标

- 不做"最好用的招聘工具"，只做"省我读简历时间的小工具"
- 不追求平台覆盖，先只做 BOSS
- 不做多用户、不做 SaaS
